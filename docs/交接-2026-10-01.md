## 常用操作

```bash
# 编译（在 a980-app 或 a980-release 里）
cargo build --release --bin a980-console        # target/release/a980-console.exe
cargo build --release --bin a980-probe          # target/release/a980-probe.exe

# 协议自检：把读到的值原样写回再比对，22 项，不弹窗口（改任何收发代码后必跑）
target/release/a980-probe.exe --verify

# 界面真机验收：起 exe 时挂远程调试端口，再跑 CDP 脚本
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222 ./target/release/a980-console.exe &
node tools/accept_test.mjs
```

`tools/accept_test.mjs` 做的事：确认页面里是 `__TAURI_INTERNALS__`（不是
合成鼠标）、invoke('refresh') 拿到真快照、UI 渲染真数据、DPI 同值写入与
灯效亮度写入都是"回读一致"才报成功、断开/重连。它是纯 Node（用内置
WebSocket），没有 npm 依赖。

## 坑（全部真机付过学费，按会再次踩到的顺序排）

1. **Tauri 命令的参数名必须和前端 invoke 的字段一字对齐**。Tauri 按参数名
   从 invoke 消息里取字段（会自动把 Rust 标识符转 camelCase），收成一个
   `Option<Value>` 大口袋是行不通的——`set_dpi` 会报 missing field `values`。
   12 个命令现在都是按前端字段名的强类型参数（src/main.rs）。
2. **`custom-protocol` feature 是生死线**：纯 `cargo build` 不带它就一律去
   连 devUrl，用户机上白屏。已在 Cargo.toml 里写死。
3. **`frontendDist` 相对 `tauri.conf.json` 所在目录**：本工程 conf 在仓库
   根部，所以是 `"frontend"`，写 `"../frontend"` dev 模式不报错、内嵌编译
   直接失败。
4. **Tauri v2 只注入 `window.__TAURI_INTERNALS__`**，不注入
   `window.__TAURI__`（`withGlobalTauri` 默认关）。前端 app.js 三种形状都认
   （`TA.core` / `TA.internals` / `__TAURI_INTERNALS__`），认不到就静默跑
   合成鼠标——界面看着连上、写入全落内存。改前端别把这三行删了。
5. **协议坑**（详见 README"真机核实过的协议细节"一节）：所有写请求 payload
   前都要多垫一个字节（固件 payload 从线缆第 7 字节起算）；按键 SET 是
   `00 k 00 功能码 数据×5`，键号后必须再跟一个 0；回读只认 class/cmd 对得
   上的帧，GET 等八轮可补发、**写命令绝不补发**；每条写命令发完必须回读
   比对，对不上就报错。
6. 从 exe 抽前端的方法（本轮首次用，可复现）：起 exe 时挂
   `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`，
   Node 内置 WebSocket 走 CDP，`Runtime.evaluate` 里
   `fetch('/app.js')` / `fetch('/style.css')` / `document.documentElement.outerHTML`。
   注意仓库根的 `a980.html` 是更早的静态原型，**没有桥代码，不是前端**。
