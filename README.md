# A980 控制台（Rust 桌面版）

达尔优 A980 游戏鼠标的参数调节器。Rust 负责 HID 收发，前端是 iOS 风格的
WebView 界面。BIOS 级的读写在一条 65 字节的 feature report 上完成，全部字段
含义逆向自 dr.dareu.com 的官方驱动，并在真机上逐条实测过。

## 为什么要做成桌面版

浏览器版本走 WebHID，问题不在协议而在选设备那一步：A980 在 Windows 里是个
复合设备，同一个产品名下挂着七八条接口（指针 1/e、键盘 1/1、系统控制 1/80、
厂商自定义 ff00/1，外加两条 usage 都是 0c/1 的用户控制接口）。WebHID 的选择框
把这几种全列成一样的一行，用户不可能靠名字勾对；而 tg 协议只活在 0c/1 那两条
上，其中只有一条带 65 字节 feature 报告、会答话，另一条 feature 长度是 0 的
纯哑接口。勾错了就表现为"弹窗里只有一个设备，点了没反应"。

桌面版没有这个问题：我们直接枚举全部接口路径自己挑，谁答得上 getFw 就用谁，
还把每个候选的身份和失败原因写进日志。

## 能调什么

- **概览**：固件/硬件版本、序列号、传感器型号与 DPI 上限、当前 DPI 与档位、
  回报率、当前配置档、电量、正在用的接口。
- **性能**：五档 DPI 独立设置（XY 可分别调、可锁定同步）、回报率
  125/250/500/1000/2000/4000/8000 Hz。
- **灯光**：按灯区分，灯效、速度、颜色、亮度。亮度在固件里是 0–255 的裸字节，
  界面上换算成百分比显示；每个灯区支持哪些灯效编号由鼠标自己报，不写死。
- **按键**：每个按键的当前功能，可改成鼠标键、双击、滚轮、DPI 档位增减、
  切换到第几档、狙击键（400/800/1600/3200）、多媒体、宏、灯效切换、Win 锁、
  恢复出厂。功能描述按官方驱动的编码规则解析。
- **系统**：屏幕语言（0 中文 / 1 English）、屏幕亮度（这台机的固件
  不支持，界面自动把那行藏掉）、当前配置档切换、忘记上次的接口、恢复出厂设置、
  收发日志。

## 编译

需要 Rust（MSVC 工具链）和 Windows 10/11。WebView2 运行时 Win11 自带。

国内网络下 rustup 和 crates.io 都极慢，建议先换源：

```bash
# 1) rustup 用 USTC 镜像
RUSTUP_DIST_SERVER=https://mirrors.ustc.edu.cn/rust-static \
RUSTUP_UPDATE_ROOT=https://mirrors.ustc.edu.cn/rust-static \
  rustup-init.exe -y --profile minimal --default-toolchain stable

# 2) crates.io 换 USTC 稀疏索引（~/.cargo/config.toml）
[source.crates-io]
replace-with = "ustc"
[source.ustc]
registry = "sparse+https://mirrors.ustc.edu.cn/crates.io-index/"
[net]
git-fetch-with-cli = true
```

然后：

```bash
cd a980-app
cargo run --release        # 编译并启动
cargo build --release      # 只出可执行文件：target/release/a980-console.exe
```

用 `cargo build --release` 直接编译（不走 `tauri build`）有两个必须注意的
地方，缺一个就会变成"能启动、界面却是 127.0.0.1 拒绝连接"：

1. **`tauri` 一定要带 `custom-protocol` feature**（`Cargo.toml` 里已经写了）。
   Tauri 只有在它打开时才把自己当发布版：前端会被编进 exe、走
   `tauri://localhost`。不打开就一律去连 `tauri.conf.json` 里的 `devUrl`，
   用户机器上什么都没有。用 tauri CLI 打包时 CLI 会自动加，纯 cargo 得自己写。
2. **`frontendDist` 是相对 `tauri.conf.json` 所在目录的**，所以是 `"frontend"`
   而不是 `"../frontend"`。写错了在 dev 模式下不报错，一开内嵌就直接编译失败。

判断产物对不对：启动应用后监控 `devUrl` 那个端口，一条请求都不该有；前端
三件套（index.html / app.js / style.css）在不在 exe 里也能从体积上看出来——v1.0
的 release 产物约 9,070,592 字节，只为对比留个数量级，具体字节数随 Tauri
小版本和主机工具链浮动，别当校验和用。

## 命令行探针

`cargo run --release --bin probe` 不弹窗口，只把一次全量读取得快照打成 JSON
打到标准输出，用来在没有图形界面的环境下验证协议：

```bash
cargo run --release --bin probe          # 连上就读一遍
cargo run --release --bin probe -- -j    # 紧凑 JSON
cargo run --release --bin probe -- --verify   # 写路径自检，见下一节
```

探针会打印每个候选接口怎么失败的，真机排障直接看这段。

## 写路径是怎么验证的

逆向来的东西，"读得出来"只算一半，"写得进去并且方向对了"才算。`--verify`
做的是一件安全的事：**把读到的值原样写回去，再读一遍比对**，不改成任何别
的值——理论上它是恒等操作，所以可以放心在真机上跑。它覆盖屏幕语言、DPI
五档与当前档位、回报率、当前配置档、灯效、灯区亮度、全部 15 个按键，
一共 22 项，实测 0 失败 0 跳过。

跑法：先存一份全量基线快照，跑 `--verify`，再存一份比对，两次逐字节一致
才说明写操作没有顺手改坏别的东西。这套流程在收尾时跑过一次，DPI 档位、
回报率、灯区亮度、按键映射全部和改动前一致。

有一项只能验到这个程度：**配置档切换只验证了"原样切回当前档"**。切到别的
档会连带改掉整套键位和 DPI，真机上没有主动试，界面上也用原文写明了这一点。

不过恒等写回有个盲区：它证明固件收下了帧，证明不了"换个值也能落盘"。所以
应用侧还有第二道——**每条写命令发完都重新读回设备值，对不上就直接报错**：
回报率、灯效、灯区亮度、按键、屏幕语言、DPI 全部如此，界面只在设备确认之后
才弹"改好了"，不一致时把"写 X 读回 Y"原样弹出来。这不是纸上谈兵：出过一回
用户把右键改成"禁用"提示成功、再改回"右键"却报"没写进去"，根因是按键写少了
一个选择字节（见下面的协议细节），固件收帧、答成功、就是不执行——只有回读
能把这种"假成功"抖出来。更早还有一回"提示改了其实没改"，根因是前端连的是
合成鼠标而不是真机（见编译第 3 条）。

## 真机核实过的协议细节

官方的 JS 驱动在这些地方和固件实际行为对不上，都是拿真机试出来的：

- **所有请求的 payload 前面都要多垫一个字节**：灯区寻址是 `00 rg`、按键是
  `00 k`、屏幕语言是 `00 值`、回报率是 `00 usb rate`。固件的 payload 是从
  线缆第 7 字节开始算的（第 6 字节恒为 0），不垫这一下它就把整个 payload
  往前错一位：要么答状态 0x03 参数不对，要么答成功但什么都不改。官方驱动
  不用垫——它的数组是把报告 ID 切掉之后的，`PAYLOAD_BASE=6` 指的正是第 7 字节。
- **DPI 写的是五档整表**，payload 是 `sensor 00 档位数据...`，不管当前是
  几档，缺的用最后一档补齐。sensor 后面那个 0 不能省，省了固件把它后面的
  字节整体前移一位，档位数量和数值全错。
- **回报率同理**是 `00 usb rate`，省掉前导字节会被拒。
- **灯区读**同样是 `00 rg`；**灯区亮度是 0–255 的裸字节**，不是百分比，
  写 0x64 读回 0x64。界面滑条因此按 0–255 走，标签换算成百分比。
- **答帧状态位**：`(状态 & 0xF) == 2` 是成功，0x03 参数不对，0x05 命令不
  支持，0xAA 还没数据。回包 payload 从字节 7 开始（第 6 字节是前导回显）。
- **这台机（固件 1.2.1）不支持的**：屏幕亮度（类 11 只有 0x83 语言这一条
  命令答话）、电池（类 7 回空包，有线鼠没有电池，界面显示"有线 · 无电池"）、
  灯区属性里的部分命令、profile 写 0x84。
- **按键写的是 `00 k 00 功能码 数据×5`**——键号后面还必须再跟一个 0（照官方
  驱动抄来的布局：`[键号, 0, 功能码, 数据]`，那 0 是第二个选择字节）。少送它，
  功能码整体前移一格，固件把功能码当成第二选择字节、把数据第一个字节当成功能
  码，拼出来无效就静默丢掉——**但仍然答状态 0x02 还回显请求，看着像成功**。
  "禁用"（功能码和数据全 0）碰巧能对上，所以这个错位只在改回真实功能码时才
  暴露：界面说"没写进去"，鼠标也确实没变。写键位必须回读比对，就是这个原因。
- **回读也要会认帧**：鼠标一次只留一个答复位，别的进程（官方驱动、上一个实例）
  留下的残帧会被当这次的答复弹回来。收发层只认类和命令号都对得上的帧，对不上就
  跳过重读；GET 命令等八轮还没人应就补发一次（写命令绝不补发，重复执行不是
  幂等的）。按键这类"寻址写在请求里"的命令还要求回显的键号一致。
- **按键 18/19 当前的功能码是 6**，官方驱动也不认识。这类功能码在按键菜单里
  没有对应项，界面只显示当前功能的名字、不能原样写回去；当前项在菜单里高亮，
  再点一次只提示"没改"，不发命令。

## 排障

- **状态胶囊一直显示未连接**：点连接按钮（或重插鼠标）。日志里会写清楚是哪条
  接口打不开、哪条问了不答话。
- **鼠标换了 USB 口之后连不上**：系统里枚举到的接口顺序可能变，点"忘记上次的
  接口"让它重新全量探测。
- **屏幕亮度读不到**：这台机的固件不支持调亮度（返回 0x05），界面上会直接省
  掉那行。
- **屏幕语言**：默认保持 0（中文）。改语言会立刻写到鼠标，掉电不丢。
- **标题下面写着"合成鼠标模式（未在桌面应用里运行）"**：说明前端没找到 Tauri
  桥，界面显示的是假数据、所有"写入"都只落在内存里。名称栏应该是
  `A980 [c/1]` 这种真实接口名。Tauri v2 只在页面注入
  `window.__TAURI_INTERNALS__`，`app.js` 三种形状都认；真出现这行就说明桥没接上，
  先看是不是页面不在 Tauri 里（拿浏览器直接打开 index.html 也会这样，那是正常的）。
- **exe 起来就 panic：`failed to create webview ... HRESULT(0x8007139F)`**：
  不是代码问题，是 WebView2 运行时被占。两种都实测过：上一轮验收崩溃留下的
  msedgewebview2.exe 死进程还挂着运行时的状态；或者同一台机上已经开着一个本应用
  （两个实例共用同一个 EBWebView 用户数据目录，第二个实例直接失败）。处理：先把
  所有 a980-console / msedgewebview2.exe 清掉，再只起一个实例；验收脚本要挂
  9222 端口的话，务必保证此前没有别处开着本应用。
- **换了图标资源管理器里还是旧图**：是 Windows 外壳图标缓存，不是 exe 没换好
  （用 `tools\extract_exe_icon.ps1` 从 exe 抽图核对即可确认）。轻则
  `C:\Windows\System32\ie4uinit.exe -show` + 刷新（F5），重则注销重登。

## 已知边界

- 恢复出厂之后鼠标会重启约两秒，期间界面会自己重连。
- **写哪一档**：灯光和 DPI 跟着"当前配置档"走——读写前都先问固件当前是第几
  档（类 5 / 0x83），写第 N 档就落在第 N 槽里，同时更新第 0 槽那份"生效中的"
  副本；探针的 `--pr <档>` 可以直接指定槽位。键位、回报率、屏幕语言不分档。
- 把某个键设成"禁用"时，鼠标可能有一瞬从 USB 总线上掉下去
  （`HidD_SetFeature: (0x00000001) 函数不正确`），这是按键真实被卸掉时的正常
  现象，一两秒内自己回来，应用会提示重连。恢复成一个鼠标键反而不会掉。
- 配置档切换只验证了原样写回，换到别的档没有在真机上试过。
- 写失败时后端会把固件的原话（比如"参数不对"）带回前端弹出来；写完还会回读
  比对，对不上照样报错。不会出现界面说"已写入"而设备其实没动的情况。
- **别让别的程序同时跟鼠标说话**（官方驱动、第二个实例、探针）。鼠标一次只
  留一个答复位，帧会串：轻则读到别人的值，重则写进去一个花掉的帧。应用内部
  有互斥锁 + 回显校验（只认 class/cmd 对得上的答复），但锁不住外部进程。
